Warehouse challenge — 5 Isolated MCP Servers (Level 5)

Five separate, read-only local DuckDB data warehouses (synthetic Jaffle Shop data), each surfaced behind its own streamable-HTTP MCP server. Connect your coding agent or custom harness to compare multi-source MCP querying against A2A delegation.

How this sandbox works:

1. Physical isolation: Each table lives in its own locked, read-only DuckDB file (orders.duckdb, stores.duckdb, customers.duckdb, order_items.duckdb, products.duckdb). Cross-table SQL JOIN, CTE, or UNION queries at a source are rejected.

2. Paging & simulated distance: Every source returns at most 500 rows per page (pass page=2, 3, ... while more: true) and adds a 100 ms simulated network delay per call. Money columns (subtotal, tax_paid, order_total, price) are in integer cents.

3. Zero-load & durable telemetry: Refreshing this page reads /metrics.json from in-memory atomic counters in <1 ms (hydrated from BigQuery on cold start and streamed asynchronously on every MCP call) so page reloads never touch DuckDB or run BigQuery queries.
